| **Acceptance Tests** | **Verify:** All links, buttons, and interactions function correctly; Input fields for sign-up, login, and filters accept and validate appropriate data; The interactive map loads and applies filters accurately; Pages present intended content without missing or misaligned elements; Responsive design works across different screen sizes. |
| **Testing Process for Key Features** | **Test Process:** Click through all navigation elements; Follow typical user journey (home page → filters → property description → apply now); Ensure users can return to the home page. **Success Criteria:** Navigation elements work as expected; No dead links; Back and forward buttons function properly. **Failure Criteria:** Incorrect navigation; Dead-end pages; Inconsistent navigation. |
| **Limitations of Acceptance Tests** | It is challenging to fully replicate real user environments or behaviors; Testers may focus on technical accuracy rather than natural behavior; Unpredictable user actions may not be captured; Edge cases (like rare invalid inputs) may not surface. |
| **User Testing Process** | **Goals:** Ensure usability, effectiveness, and relevance of the platform. **Recruitment:** Diverse UW students (low-income, marginalized, international, etc.); Test app for both commuters and on-campus residents. **Methods:** Task-based testing; Think-Aloud Protocol; Surveys & Interviews. **Data Collection:** Quantitative (success rates, task completion time); Qualitative (feedback, frustrations, suggestions). |
| **Bug Fix Prioritization** | **Critical Bugs:** Break key features (e.g., navigation, login, filters); **Performance/Accessibility:** Slow load times, poor mobile view, accessibility barriers; **Minor Bugs:** Cosmetic issues, minor performance lags. Fix order: Critical → Performance → Minor. |
| **Re-Testing After Bug Fixes** | Re-test all related features; Verify the fixed bugs; Simulate real user interactions; Continuously test original acceptance criteria to ensure expectations are met. |
